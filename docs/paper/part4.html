CHAPTER 16

The pipeline, the wall and the Rust service

One script does all the heavy work once a day and writes small files; the app only reads them; a Rust service reproduces the mathematics from raw prices and refuses to start unless it can prove it. Everything between is tested, versioned and tagged.

16.1 One daily pipeline, register-a-stage

pipelines/run_daily.py runs every weekday at 06:00 UTC in GitHub Actions. Models are loaded, never fitted; refits are a separate, deliberate make refit that bumps a version, rebuilds the validation report and re-exports the bundle. Every stage runs in memory and all artifacts are written in one final stage, so a failure anywhere leaves the data directory exactly as it was and the app keeps serving the last good state. A stage is one function and one registration line:

dataYahoo download · ECB cross-check · drop bad ticks · exclude the in-progress day
featuresnine causal features per pair
hmmforward filter with the saved bundles → regime, probs, entropy, run length
cb_features · features_extlexicon tone · calendar, context, COT, YZ → challenger matrix
forecaster · challengerXGBoost + SHAP drivers → change_risk_5d (+ _ch)
sirenautoencoder → anomaly score & percentile
bocpd · conformal · driftrun length, votes, band, status.json
ledgerappend newest forecasts · resolve matured · scoreboard · head
narratorthree sentences, LLM or template
postmortem · advisor · treasury · arcadecrisis draft · stability · VaR/ES table · resolve calls
writeall artifacts at once + pipeline_status.json

A full run takes about 20 seconds on a laptop. The daily Action then commits the refreshed artifacts — including the ledger head — back to the repository; a second Action publishes the Monday report; CI runs the 273 tests, the lint, the design-token check and the public ledger verifier on every push; a Rust workflow runs cargo test, clippy and the golden self-test.

16.2 The wall: the only thing that crosses is a bundle

Python is the research side — training, validation, narration, export. The production serving path is Rust and imports nothing from Python at runtime. The versioned bundle models/bundle_v1.4.0/ contains the forecaster and siren as ONNX graphs, the three HMMs as JSON (means, covariances, transition matrix, start probabilities, scaler, mapping), a feature_spec.yaml that pins every feature's definition and window, 302 golden vectors (raw 600-day windows per pair with their expected features and outputs) and a manifest of SHA-256 hashes. Pickle never crosses. The Rust crate rebuilds the features from raw prices — including three pairwise rolling correlations with pairwise calendars — and the 540-step forward filter, and at startup replays every golden: features must match to 10−8, model outputs to 10−6, or the service refuses to bind its port. That gate has stayed byte-identical through every later phase.

benchmark (laptop, release build)result
one pair, full path: raw 600-day windows → features → HMM filter (540 steps) → forecaster.onnx → siren.onnx≈ 0.43 ms per call (single thread)
throughput, 10,000 full-path calls≈ 2,260 rows/s
startup gate: hash verification + 302-golden self-test≈ 0.4–0.5 s
POST /api/score, 8 concurrent clients, real windows (~55 KB JSON each)≈ 2,180 req/s · p50 3.6 ms · p99 4.4 ms
GET /api/regimes/{pair} (mtime-cached newest rows)≈ 9,600 req/s · p50 0.38 ms

Honest reading, from the bench notes: the ONNX calls are microseconds; almost all of the 0.43 ms is recomputing 600 rows of features and the forward filter from scratch on every call — the price of a stateless path that reproduces Python bit-for-bit. A streaming server carrying yesterday's state would be one to two orders of magnitude faster, at the cost of state to keep correct. For a daily product with three pairs, 0.43 ms is irrelevant; the number that matters is the gate.

16.3 From service to product

Around the unchanged engine the service grew an identity layer and a push channel. Keys: X-API-Key, stored as SHA-256 hashes only in SQLite, with free / pro / partner tiers, a per-key token bucket (429 with Retry-After) and a small admin CLI that prints a key exactly once. Alerts: a background poller watches the newest artifact rows for three triggers — a regime flip, a siren above 98, a 3/3 consensus — and delivers HMAC-SHA256-signed JSON to registered webhooks (generic, Slack, Telegram) from a queue with exponential backoff and at most five tries; a persisted last-alerted state makes the same regime two days in a row exactly one alert. Delivery never happens inside a request handler. The template text is linted for direction words. Menu: OpenAPI via utoipa with Swagger UI at /docs; Prometheus /metrics (requests, latency histograms, alerts fired, delivery outcomes). Surfaces: an embeddable /widget.js badge (regime dot + word + siren), GET /api/treasury reading the treasury artifact with arithmetic only, and a Stripe test-mode webhook that verifies the signature and moves a key between tiers. Secrets live in environment files; the key database is gitignored; the deploy notes target a systemd unit on an Oracle always-free VM or Cloud Run, with /api/health as the check.

Interview lens

"Why Rust for serving a Python model?" Not speed — discipline. A second implementation that must reproduce the first to 10−8 from raw prices is the strongest test of the feature definitions that exists; the goldens catch any drift between research and production the day it happens. "Why hash the API keys?" A leaked database cannot be replayed. "What breaks if alerts fire inside the handler?" Request latency depends on a third party's webhook, and a timeout loses the alert — push needs a queue and idempotent state, not a function call.

CHAPTER 17

A trust-first interface

For a risk product, credibility out-attracts flash. The interface was evolved to a single target mock-up: the full market state readable in three seconds from two metres, the evidence of the record never below the fold, one ambient element and nothing else that moves.

17.1 One token file, enforced

design/tokens.json is the only source of colour, type and motion: surfaces (nimbus #0E1420, front #151D2E, a hairline at 8 % white), text (#E8ECF4 / #9AA6B8 / a dim tone lifted from the mock-up's value to clear 4.5:1), regime colours used for data and status only (calm #3ECF8E, trend #4DA3FF, chop #F5B942, crisis #FF5C5C), one accent for links and actions. A tiny loader exposes the tokens to Python; a generator writes the Streamlit theme file, a CSS file and the Rust static tokens; the Plotly template, every matplotlib report figure, the orb's presets, the e-mail report and the widget read from the same place. make lint-ui runs in CI and fails on any hex literal anywhere else; a test checks that every text/surface pair clears 4.5:1 on both surfaces, that no font weight above 500 is used, and that the motion budget is exactly two animations — the orb and the live dot's pulse — both disabled under prefers-reduced-motion. Type is Space Grotesk for the regime word and page titles, IBM Plex Sans for the interface, IBM Plex Mono with tabular figures for every number, hash and ledger value; numbers are right-aligned in tables.

17.2 Two signature structures

The condition banner replaces the old hero row: an eyebrow with the pair and the data-through date; the regime word huge in its colour; one metrics line — change risk with its 90 % band, siren out of 100; the quiet 90-day risk trace with the shaded band; and the three-dot consensus module. Regime is never colour-only — the word and a dot carry the state, colour only repeats it. The trust strip sits under it on every surface: forward-test day count, live Brier against frozen, coverage against the 90 % target, the chain head with its check, and "verify independently". If anything competes with the banner, the element is quieted — the orb moved to the Pairs page for that reason.

17.3 Information architecture

Radar: Overview · Pairs · Treasury · Storms · Proof. Analysis: Advisor · Regime space · Probability space · Strategy lab · Arcade. About: Methodology · Weekly report · Metrics. Every widget had to answer "what does the user decide with this?" or move to Analysis. Empty, loading and error states say what happened and what to do — never apologise, never vague. The app reads artifacts only and paints in about a second.

CHAPTER 18

Go-to-market: a free weekly report, three tiers, five partners

A risk product for treasurers is not sold with ads. It is sold with a useful page every Monday, forwarded by one treasurer to another, and with a public record that does the talking. The plan is small on purpose.

18.1 The weekly FX weather report

Every Monday at 06:30 UTC a second Action generates a report from the committed artifacts — per pair: regime, change risk ± band, siren, a generic hedge / wait / ladder light (the same public fact for every reader; never personalised, because a personalised light is suitability advice), days to the next SNB / ECB / FOMC / BoE decision, the narrator's three template sentences, the live-record line and a link to the Proof page — as Markdown, as an e-mail-safe light-mode HTML twin (inline styles, 360-pixel checked) and as an RSS feed. An ops-log line records each publication so that a silent Monday is visible. Zero paid services; the e-mail provider is a documented hook for later.

18.2 Five design partners before fifty sign-ups

The outreach kit is in the repository: a design-partner e-mail in German and English (under 150 words — six months free for a monthly feedback call and a signed letter of intent at CHF 79 a month if the product proves useful), a one-page LOI template, the target criteria (Swiss SMEs with EUR/USD invoicing, fiduciary firms, treasury associations) and a tracking sheet with fifteen placeholder rows. Five partners beat fifty sign-ups because a partner makes the real decision monthly, gives feedback, and signs — evidence of willingness to pay that a free user can never provide. The roadmap rule after this phase is explicit: no new code before ten treasurer conversations.

CHAPTER 19

Limitations and roadmap

A report that hides its limits is marketing. These are the ones the author would raise first.

Data

  • Free Yahoo daily bars: occasional bad ticks (dropped), a start-of-day close convention, no intraday detail, no tradable spreads. The methodology transfers to a clean feed; the numbers would move a little.
  • Three pairs. EUR/CHF — the Swiss treasurer's own cross — is a context series, not a scored pair, precisely because a pegged cross blinds a volatility-based radar for years at a time.

Models

  • The HMM's trend/chop split is seed-fragile (40–100 % agreement across seeds); the calm/crisis ends are stable. A seed ensemble or a duration-explicit variant is the obvious next step. USD/CHF's crisis state is a single event.
  • The forecaster's label is the HMM's own filtered decision, so it inherits that fragility; PR-AUC 0.548 is a clear margin over logistic but no one should read it as a market call. The challenger with calendar and context did not lift it.
  • Conformal bands on a binary outcome are wide by nature (q 0.5–0.8); they are honest, not decorative. Exchangeability is violated; only the empirical receipt is claimed.
  • The strategy layer loses net of costs on every stance and every window; it is shipped as a finding, not a result.
  • The central-bank index has no credible surprise effect yet on 184 statements, and the language-model leg has, correctly, scored nothing so far.

Engineering and product

  • The live record is two days old at the time of writing; every "live" number says "warming up" until twenty rows mature. That is the point — but it means the strongest claim in this document cannot be made yet.
  • Alert adapters were tested against local receivers and synthetic secrets; the FinBERT leg has never actually run; Stripe is in test mode; nothing is deployed publicly yet.
  • Legal texts are drafts; Swiss FinSA specifics need a professional before any charge.

CHAPTER 20

Interview companion: questions, answers, critiques

The questions a quant, a risk manager, an ML engineer and a product lead actually ask — with the answer this project earns, and the honest weak spot in each.

Q. How do you know your features do not leak?

Every feature module has a truncation-invariance test: computing on data cut at T must reproduce rows ≤ T bit-for-bit. The HMM uses the forward filter, never the smoother; every scaler, PCA, quantile and threshold is fitted on training rows only and stores its train_end. Weak spot: a test proves what it tests; the discipline has to be applied to every new feature, which is why the rule is in the constitution and the CI.

Q. Why is the test set scored only once?

Because every look is a degree of freedom. Train ≤ 2016, validation 2017–18 chose early stopping, the threshold and the conformal quantiles; test 2019+ was scored once per model and frozen. New evidence goes to the live ledger, where it cannot be re-chosen. Weak spot: "once" relies on discipline; the published numbers and the git history are the audit trail.

Q. Why PR-AUC and Brier, not accuracy or ROC?

A 16 % positive rate makes accuracy meaningless and ROC flattering. PR-AUC scores the rare class we care about; Brier scores the calibration of the probabilities the product actually shows; both are reported next to a base rate, a logistic model and a one-feature rule. Weak spot: PR-AUC on five-day windows of an autocorrelated label over-counts effective sample size; the ledger's live Brier is the cleaner number.

Q. A monthly refit lands — what happens to the record?

The refit carries a new model version; the ledger starts a new segment; the scoreboard shows both; the headline scores the current segment only. Old rows keep their hashes; the chain is unbroken; the old record cannot be laundered by the new model. Weak spot: a refit also resets the warm-up clock for the headline.

Q. What does a GitHub commit add that local hashing cannot?

Time. A hash proves content; it does not prove when. The daily Action commits ledger_head.txt, and GitHub's commit timestamps — outside the author's control — fix the moment the chain head existed. Weak spot: GitHub is a trusted third party; a public timestamping service would be stronger.

Q. "3-D charts are gimmicks." Defend the tetrahedron in a minute.

Four probabilities that sum to one live on a 3-simplex; the tetrahedron is their exact geometry, not a projection — no fitting, no scaling, axes hidden because the coordinates have no units. It shows at a glance whether the filter is decisive (path near vertices) or unsure (path near the centroid), and it is display-only: no model output changed to make it. Weak spot: it is still a picture; the operational views are 2-D on purpose.

Q. Why does every strategy lose money, and why ship it?

Daily-bar FX timing with a mechanical stance does not survive a realistic, volatility-scaled cost model; the breakeven cost multiplier is zero. It is shipped because the models' purpose was never to trade, and because a documented negative with its cost model, turnover and stress table is the strongest possible answer to "what did you do to the data?". Weak spot: a reader who skims for a Sharpe will leave.

Q. Where is the line between risk information and investment advice?

Risk information is a property of the market conditioned on published numbers, the same for everyone: "given today's regime, the 99 % one-week expected shortfall is X". Advice is about what you should do given your position. The treasury light is a public rule table; the page stores no positions; every surface says it is educational. Weak spot: Swiss FinSA specifics need a professional before any charge.

Q. FinBERT aces 2015 letters in a test — why is that worthless?

Because its weights were trained on text written after 2015, including descriptions of what happened next. The leak is parametric, not in the pipeline; the score measures memory of the ending. The only honest test of a model with memory is forward, on post-cutoff text, with receipts. Weak spot: forward evidence accrues slowly — forty letters a year.

Q. Why Rust for serving?

A second implementation that must reproduce the first from raw prices to 10−8 is the strongest test of the feature definitions, and a startup gate that refuses to serve on mismatch turns "research drifted from production" from a silent bug into a loud one. Weak spot: two implementations cost two maintenance budgets; the goldens are what make that affordable.

Q. Someone proposes animating the siren dial. Accept or decline?

Decline. The motion budget is the orb plus the live dot; a third animation competes with the condition banner, and a moving dial on a reading surface invites the eye to a number that is already in text. Weak spot: it would look exciting in a demo — which is the reason to decline it.

APPENDIX A

Glossary · reproducibility · repository tour

Glossary

Regime
One of four latent market conditions — calm, trend, chop, crisis — inferred by the HMM from returns, volatility and momentum; describes conditions, never direction.
Filtered vs smoothed
Filtered: P(state at t | data ≤ t). Smoothed: P(state at t | all data). Only filtered is causal.
Change risk
Probability that the filtered regime differs on any of the next five trading days; Platt-calibrated XGBoost output.
Siren / anomaly percentile
Reconstruction error of a calm-trained autoencoder, ranked against calm training days; 98+ is the action line.
BOCPD · run length · hazard
Bayesian online changepoint detection; days since the last changepoint; the prior probability of a changepoint each day (1/60).
Consensus / agreement
Count (0–3) of HMM, BOCPD and vol-rule votes that see stress, each with a training-era threshold.
Conformal band · Mondrian
p̂ ± q with q the 90 % quantile of |y − p̂| on validation; Mondrian = one q per regime. Coverage is reported empirically.
Embargo
Five trading days dropped on both sides of every split boundary so forward-looking labels cannot straddle it.
Lag law
A signal formed at close t earns returns from t+1; enforced inside the backtest engine.
Breakeven cost
The multiple of the cost model at which a strategy's net Sharpe reaches zero.
Ledger · chain head
Append-only record of forecasts hashed before outcomes exist; the last hash, committed daily.
PSI · KS
Population stability index and Kolmogorov–Smirnov statistic, train era vs the last 60 days.
The wall · bundle · goldens
Research (Python) / production (Rust) separation; the versioned ONNX+JSON artifact; the 302 vectors the service must reproduce at startup.
Parametric look-ahead
Leakage through a model's weights rather than through data: it has read the ending.
VaR · ES
Quantile of the absolute weekly move; mean beyond it — regime-conditional, training era, historical simulation.

Reproducibility

Python 3.11, pinned top-level dependencies, black + ruff, 273 pytest tests (~70 s, no network, no key). Rust stable, cargo test + clippy + fmt. Every phase is a tagged commit (v0.1.0 → v2.21.0) with a changelog entry and a verify block.
