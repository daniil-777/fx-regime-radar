# FX Regime Radar — HTTP API (Rust service, phase 24)

The `fxradar-serve` binary (`rust/fxradar-serve`) serves the computed state from the frozen model
bundle and the pipeline's artifacts. It refuses to start unless every golden vector reproduces
(the start-up gate, phase 13). Everything below is added *around* that gate: nothing in a handler
does model math, and nothing in a handler calls a third party.

Interactive docs: **`/docs`** (Swagger UI, generated by `utoipa`); raw spec: `/api-docs/openapi.json`.

> Educational tool. Not investment advice. The API reports regimes, change risk and anomalies —
> never a price direction. Every alert text and every treasury response carries this sentence.

## Routes

| Route | Auth | Purpose |
|---|---|---|
| `GET /api/health` | public | version, bundle, self-test verdict, uptime, engine p50/p99 |
| `GET /api/regimes/{pair}` | public | newest `regimes.parquet` row for EURUSD / USDCHF / GBPUSD (+ `served_by`, `bundle_version`); `?partner=` is logged for widget attribution only |
| `GET /metrics` | public | Prometheus text format (see below) |
| `GET /widget.js`, `GET /widget` | public | embeddable badge script + demo page |
| `GET /docs`, `GET /api-docs/openapi.json` | public | Swagger UI / OpenAPI 3.1 |
| `POST /api/stripe/webhook` | Stripe signature | tier changes from Stripe (test mode) |
| `POST /api/score` | key, **pro \| partner** | score raw 600-day windows through the bundle |
| `GET /api/treasury` | key, **pro \| partner** | `data/treasury_risk.json` + optional notional arithmetic |
| `POST /api/webhooks`, `GET /api/webhooks`, `DELETE /api/webhooks/{id}` | key, **pro \| partner** | alert receivers for the calling key |

Error bodies are always JSON: `{"error": "...", "status": 401}`.

## Authentication, tiers, rate limit

* Header: `X-API-Key: fxr_…`. Keys are random 32-byte values; the service stores **only the
  SHA-256 hex** (sqlite, `data/keys.db` by default — `--keys-db` / `FXRADAR_KEYS_DB`). The file is a
  secret (it also holds webhook secrets and Telegram bot URLs): never commit it.
* Tiers: `free` (public routes only — weekly report, widget), `pro` (alerts, treasury, scoring API),
  `partner` (same plus white-label widget attribution). Unknown tier strings are treated as `free`.
* Responses: missing/unknown/revoked key → **401**; valid key on a wrong tier → **403**;
  over the per-key token bucket (default 60 req/min, burst 60; `--rate-limit-per-min` /
  `FXRADAR_RATE_LIMIT_PER_MIN`) → **429** with `Retry-After: <seconds>`.
* Admin CLI (on the server, same db):
  ```bash
  keys issue --label "acme treasury" --tier pro     # prints the plaintext ONCE
  keys list                                         # hash prefix, tier, revoked, created, last used
  keys set-tier c9f1c459d475 partner
  keys revoke   c9f1c459d475
  keys webhooks                                     # registered receivers, secrets hidden
  ```

```bash
curl -H "X-API-Key: $KEY" https://HOST/api/webhooks
curl -H "X-API-Key: $KEY" "https://HOST/api/treasury?pair=EURUSD&amount=800000&weeks=2&level=0.99"
# → {"calc": {"es_notional": amount × es_1w × sqrt(weeks), ...}, "artifact": {...}, "disclaimer": "..."}
```

## Alerts (webhooks)

Register a receiver; the signing secret is returned **once**:

```bash
curl -X POST https://HOST/api/webhooks -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/fxradar", "kind": "generic", "pairs": ["EURUSD", "USDCHF"]}'
# {"id": 1, "secret": "whsec_…", "signing": "X-FXRadar-Signature: sha256=hex(HMAC-SHA256(secret, \"{X-FXRadar-Timestamp}.{raw body}\"))", ...}
```

`kind`: `generic` (full JSON payload), `slack` (`{"text": …}` to a Slack incoming-webhook URL),
`telegram` (`{"chat_id", "text"}` to `https://api.telegram.org/bot<TOKEN>/sendMessage`; pass
`chat_id`). `pairs` empty = all pairs. At most 10 receivers per key.

Triggers, evaluated by a background task every `--alert-poll-secs` (default 300 s, once at start-up)
against the newest row per pair, **per key and pair, edge-triggered and persisted** — the same
regime two days in a row produces exactly one alert, a receiver that registers today gets the
current regime once:

| event | fires when |
|---|---|
| `regime_flip` | the regime word differs from the last alerted one for this key+pair |
| `anomaly` | `anomaly_pct` crosses above 98 (silent while it stays there) |
| `consensus` | `agreement` becomes 3/3 (column absent → never fires) |

Delivery is at-least-once on a tokio queue, never inside a request: up to 5 tries with
exponential backoff (2 s, 4 s, 8 s, 16 s), then it gives up with a log line and
`alert_deliveries_total{outcome="gave_up"}` +1. Receivers must therefore be idempotent on
`(event, pair, date)`.

Headers on every delivery: `X-FXRadar-Signature: sha256=<hex>`, `X-FXRadar-Timestamp: <unix>`,
`X-FXRadar-Event: regime_flip|anomaly|consensus`, `X-FXRadar-Webhook-Id`.

Verify (the whole client, `tools/verify_webhook_sig.py`):

```python
import hashlib, hmac
def genuine(secret: str, timestamp: str, signature: str, raw_body: bytes) -> bool:
    mac = hmac.new(secret.encode(), f"{timestamp}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest("sha256=" + mac, signature)
```
Reject timestamps older than a few minutes if you care about replay.

Example `generic` payload:

```json
{
  "event": "regime_flip", "pair": "EURUSD", "date": "2026-08-18", "regime": "calm",
  "change_risk_5d": 0.0148, "risk_lo": 0.0, "risk_hi": 0.508, "anomaly_pct": 73.1,
  "agreement": 0, "consensus_text": "0/3 agree: quiet conditions — no voter sees stress",
  "next_event": {"date": "2026-09-04", "type": "NFP", "source": "bls.gov"},
  "text": "FX Regime Radar · EURUSD · 2026-08-18\nTrigger: regime changed to calm\nRegime: calm\nChange risk (5d): 1.5% (interval 0.0%–50.8%)\nConsensus: 0/3 agree: quiet conditions — no voter sees stress\nNext scheduled event: NFP on 2026-09-04 (bls.gov)\nEducational tool. Not investment advice.",
  "disclaimer": "Educational tool. Not investment advice.",
  "sent_at_utc": "2026-08-19T14:01:00Z", "source": "fxradar-serve"
}
```
The text template is unit-linted against direction words (rise, fall, up, down, buy, sell, long,
short, target, bullish, bearish, rally, drop, crash) and always ends with the disclaimer.

## Scoring

```bash
curl -X POST https://HOST/api/score -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"pair": "EURUSD", "windows": [{"pair": "EURUSD", "dates": [...days since epoch...], "close": [...], "high": [...], "low": [...]}, {"pair": "USDCHF", ...}, {"pair": "GBPUSD", ...}]}'
```
All three pairs' windows (≥ 600 rows, oldest first) are needed because `corr_20` is pairwise.
`tools/load_check.py` builds a real request from `data/prices.parquet`.

## Metrics (`/metrics`)

`http_requests_total{route,status}`, `http_request_duration_seconds{route}` (histogram),
`score_requests_total`, `score_latency_seconds` (engine only), `alerts_fired_total{trigger}`,
`alert_deliveries_total{outcome="ok"|"retry"|"gave_up"}`, `alert_poll_total{outcome}`,
`widget_requests_total{partner}`. `/api/health` keeps the p50/p99 engine counters from phase 13.

## Widget

```html
<script src="https://HOST/widget.js?partner=yourname" data-pair="EURUSD" async></script>
```
Renders a badge (regime dot + word, `siren p<anomaly_pct>`, change risk, disclaimer line) from
`/api/regimes/{pair}` on the script's origin. `?partner=` is only logged/counted. Demo: `/widget`.

## Stripe (phase 28, test mode)

`POST /api/stripe/webhook` verifies `Stripe-Signature` (`t=…,v1=…`, HMAC-SHA256 of `{t}.{payload}`
with `STRIPE_WEBHOOK_SECRET`, 5-minute tolerance — 400 on failure, 503 if the secret is unset).
Create Checkout Sessions with `client_reference_id = <key hash prefix from keys list>`,
`subscription_data[metadata][key_prefix] = <same>` and prices whose `lookup_key` is `pro` or
`partner`. `checkout.session.completed` / `customer.subscription.updated` → that tier;
`customer.subscription.deleted` or a canceled/unpaid status → `free`. No live charges before the
terms/privacy pages exist (phase 28 req 3).

## Running it

```bash
cd rust/fxradar-serve && cargo build --release
FXRADAR_KEYS_DB=data/keys.db STRIPE_WEBHOOK_SECRET=whsec_… \
  target/release/fxradar-serve --bundle models/bundle_v1.4.0 --data-dir data --bind 0.0.0.0:8080
target/release/keys --db data/keys.db issue --label first --tier pro
```
Flags / env: `--keys-db` (`FXRADAR_KEYS_DB`), `--rate-limit-per-min` (`FXRADAR_RATE_LIMIT_PER_MIN`),
`--alert-poll-secs` (`FXRADAR_ALERT_POLL_SECS`, 0 disables alerts), `STRIPE_WEBHOOK_SECRET` (env only).
